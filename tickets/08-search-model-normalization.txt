Title: Include normalization mode in every packaged model search

Criticality: Medium
Estimated effort: Low
Type: Model-selection improvement

Description:
Hyperparameter searches should evaluate the input-normalization strategy for
every model that provides a packaged search configuration rather than fixing
it before optimization. Normalization changes the information presented to a
model and can interact with architecture, learning rate, and regularization.

The repository currently provides search entry points and configurations for
six trainable models: EfficientNet-1D and EfficientNet-2D in B0, B2, and B4
variants. All six already support normalization values of "dataset", "sample",
and "none", and the shared search utility supports categorical parameters.
Normalization can therefore be searched without changing the public training
APIs or optimization framework.

IQ XCiT has source-backed training but no packaged hyperparameter-search path.
Spectrogram XCiT and DETR appear only as stale compiled cache artifacts in this
checkout, not maintainable source. Normalization should be included when a
supported search path for any of those families is introduced, but creating
new model/search stacks is outside this ticket.

Evidence:
- torchsig_models/models/iq_models/efficientnet/search_configs/*.yaml and
  torchsig_models/models/spectrogram_models/efficientnet/search_configs/*.yaml
  previously omitted normalization from their search spaces
- torchsig_models/utils/hyperparameter_search.py supports categorical search
  parameters through Optuna suggest_categorical
- runs/normalization_comparison/comparison.csv reports validation macro-F1 of
  0.247 for sample normalization, 0.232 for dataset normalization, and 0.228
  with no normalization in a controlled EfficientNet-2D experiment
- The same experiment reports shifted-test macro-F1 of 0.238 for sample
  normalization, compared with 0.155 for dataset normalization and 0.151 with
  no normalization, showing that the choice can materially affect robustness

Proposed resolution:
Add normalization as a categorical parameter with choices [dataset, sample,
none] to every packaged EfficientNet-1D and EfficientNet-2D search
configuration. Increase the default trial count from 20 to 30 so adding the
categorical dimension does not reduce coverage of the existing continuous
parameters as sharply.

Keep validation F1 as the default objective, but document that it selects for
in-distribution validation performance rather than shifted-test robustness.
Require future packaged model searches to expose normalization when the model
supports multiple input-normalization modes.

Dataset normalization requires an additional pass over the training loader in
every applicable trial. This ticket does not solve that performance issue;
tickets/performance/07-cache-normalization-statistics.txt tracks caching the
computed statistics.

Acceptance criteria:
- All six packaged EfficientNet-1D and EfficientNet-2D model configurations
  expose normalization as a categorical choice containing dataset, sample,
  and none.
- The default trial budget is reviewed and adjusted for the additional search
  dimension.
- Suggested normalization values are forwarded unchanged to training and
  recorded in trial hyperparameters.
- Best-trial training-parameter output preserves the selected normalization
  mode so the result can be reproduced.
- Tests cover every packaged search configuration plus both the IQ and
  spectrogram search orchestration paths.
- Dataset statistics continue to be computed from the training split only and
  checkpoint metadata continues to preserve the chosen normalization state.
- Search documentation distinguishes validation-objective selection from
  evaluation on shifted or out-of-distribution data.
